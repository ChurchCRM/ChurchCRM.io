The moment many ChurchInfo congregations have been waiting for is here.

ChurchCRM 7.4.2 ships with the most complete ChurchInfo migration path we've ever built, closes three security vulnerabilities (two rated critical), and delivers a redesigned upgrade experience that makes transitions — whether you're coming from ChurchInfo or an older ChurchCRM version — significantly smoother.

## ChurchInfo 1.3.1 Migration: Finally Flawless

For years, congregations running ChurchInfo 1.3.1 hit a specific, frustrating wall when trying to migrate: legacy MD5-encrypted passwords would fail silently after restore, leaving users locked out of the new system on day one. 7.4.2 resolves this completely.

ChurchCRM now automatically detects legacy MD5 password hashes during restore and upgrades them on import. Every account comes through with working credentials — no manual password resets required.

The migration path is direct:

1. **Back up your ChurchInfo database** as a `.sql` file using phpMyAdmin or your host's tools
2. **Download and install ChurchCRM 7.4.2** from [churchcrm.io](https://churchcrm.io)
3. **Run the setup wizard** — when prompted to restore from backup, upload your ChurchInfo `.sql` file
4. **ChurchCRM upgrades the schema automatically** — members, families, contact info, giving history, and group memberships all come through

Beyond ChurchInfo, we've also consolidated 29 individual legacy migration steps into a single, efficient process — dramatically reducing the risk of database timeout errors when upgrading from older ChurchCRM versions directly to 7.4.2.

## Three Security Vulnerabilities Closed — Two Critical

This release patches three security vulnerabilities in ChurchCRM, two rated critical. The most significant involved unauthorized access to pledge and fundraising data — financial records that should be strictly gated are now protected by hardened permission blockades that cannot be bypassed through URL manipulation or parameter tampering.

If you're running ChurchCRM on a publicly accessible server and haven't updated to 7.4.2, we strongly recommend doing so now.

## Permission-Aware UI: If You Can't Access It, You Won't See It

7.4.2 ships a fundamentally smarter permissions model. The main sidebar and navigation menus are now fully permission-aware: if a staff member or volunteer doesn't have access to a tool, that menu item simply doesn't appear. No dead links, no "Access Denied" errors, no confusion for volunteers who shouldn't be seeing finance pages anyway.

For users with no special permissions assigned, a safe baseline gives read-only access to household profiles and the church directory — just enough to do their job, nothing more.

## Redesigned Upgrade Wizard and User Audit Tools

Before any upgrade, administrators now see an interactive "Upgrade Path Panel" with a target version selector and the full release notes displayed directly inside the application. You know exactly what's changing before you commit to the upgrade.

The Admin Users screen also gains a new "Status" column — at a glance you can see which accounts are active, locked, or flagged for a required password change. Account hygiene that used to take digging now takes seconds.
