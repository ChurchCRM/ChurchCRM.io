# ChurchCRM International Marketing Plan

## Purpose

Turn ChurchCRM's international and localization strength into a focused acquisition strategy without assuming every language or country deserves equal investment.

## Strategic premise

ChurchCRM's international advantage is more than translation. The application supports translated interfaces and regional localization, including date/time, phone, timezone, currency, and other locale-sensitive presentation.

The website currently supports a smaller set of languages than the application. That gap is an opportunity, but translating everything indiscriminately is not the strategy.

## Principles

- Language and country are separate dimensions.
- Localization is more important than a language-count headline.
- Prioritize markets by adoption potential, not population alone.
- Use current product capability as the foundation.
- Measure success by downloads/installs, not follower counts.
- Localized content should preserve the same ChurchCRM positioning and product truth.
- Localized marketing should sound natural to the target community, not machine-translated.
- Search demand must be researched in the target language/market rather than assumed from English translations.

## Current website language footprint

The current Hugo site is configured for English, Spanish, Portuguese, Chinese, French, Russian, German, and Arabic.

The application/documentation language footprint is broader. The exact current count should be verified from the application before being used in public copy.

## International SEO strategy

International SEO is a first-class part of this plan.

### URL and language architecture

Before expanding localized content, document the chosen URL model and keep it consistent. For the existing localized site, audit every language URL and establish:

- canonical URL for each localized page
- reciprocal `hreflang` relationships
- appropriate language-region codes where actual content supports them
- `x-default` behavior where appropriate
- sitemap inclusion for localized URLs
- internal links between language variants where useful
- protection against translated pages accidentally canonicalizing to English

Do not assume that a translated page automatically has correct international SEO. The implementation must test the actual rendered tags and canonical relationships.

### Localized keyword research

Do not translate the English keyword list literally and assume it matches local search behavior.

For each priority market, research:

- category terms used locally for church management software
- church CRM/database terms
- workflow terms such as membership, attendance, giving, groups, and check-in
- “free” and “open source” variants in the local language
- alternative/comparison searches
- installation/self-hosting searches
- terminology used by local churches and competing products

The output should include the local query, translated meaning, search intent, observed demand where available, current SERP results, ChurchCRM fit, and recommended destination page.

### Per-market SERP reality check

For every market considered for meaningful investment, inspect the actual local SERP before deciding what content to create.

Record:

- who ranks
- what page types rank
- commercial vs informational intent
- local competitors
- directory/community results
- whether ChurchCRM has a credible content/product advantage

The purpose is not to chase rankings blindly. It is to find markets where the underserved/localized thesis has evidence.

## Opportunity matrix

Build and maintain a matrix with:

| Dimension | Example question |
|---|---|
| Language | Is the interface/content available? |
| Country | Which countries plausibly need the product? |
| Existing users | Do we already have evidence of adoption? |
| Website localization | Does a localized landing experience exist? |
| CRM localization | Is the application sufficiently localized? |
| Local search demand | What do churches actually search for? |
| Local SERP | Who/what currently ranks? |
| Competition | Are mainstream products strong/weak in the market? |
| Affordability fit | Is free/open-source materially valuable? |
| Self-hosting fit | Is ownership/deployment a meaningful advantage? |
| Community | Are contributors/translators/partners available? |
| Adoption potential | Can the market plausibly produce installs? |
| Social priority | Is there a useful channel/community to reach? |

## Priority scoring

A practical score can combine:

- existing adoption evidence
- product localization readiness
- website readiness
- local keyword/search opportunity
- local SERP/competitive gap
- affordability fit
- self-hosting fit
- community reach
- expected installation potential

The model should be transparent enough that contributors can challenge the assumptions.

## Language strategy

Do not require every English campaign to be translated into every supported language.

Instead:

1. Identify the audience and problem.
2. Identify countries/languages with meaningful opportunity.
3. Research local search demand and SERPs.
4. Check product and website readiness.
5. Localize content that has a realistic path to adoption.
6. Use local examples and terminology.
7. Measure installations/downloads.
8. Increase or decrease investment based on evidence.

## Country strategy

A language can represent many different markets. Spanish, Portuguese, English, and Arabic should each be evaluated across relevant countries/regions rather than treated as one homogeneous market.

Country targeting should account for church structures, hosting norms, payment/giving practices, internet access, local terminology, competing software, and community channels.

## Localized messaging

The core story should remain consistent:

> Church management software you can actually start with.

Then adapt the proof:

- free and open-source software
- localized experience
- ownership/self-hosting
- practical church workflows
- community/open source

Do not translate slogans literally when a culturally natural expression communicates the same idea better.

## Localized visuals

The Playwright Visual Media Pipeline should be able to generate selected localized screenshots with translated UI, regional date/currency formatting, timezone context, and RTL layout where applicable.

Use localized visuals when they improve comprehension or trust.

## Social strategy

Select channels by actual community presence. Potential channels include LinkedIn, Facebook, Instagram, X, Reddit, YouTube, local church technology communities, regional church forums, and partner communities.

Do not create a social account for every country simply because the language is supported.

## Community-led international growth

International growth should invite translators, church administrators, regional users, documentation contributors, testers, developers, and community ambassadors to participate.

> ChurchCRM is open source. If your church or country needs something we are missing, help us make it better.

## Attribution

All campaign links to ChurchCRM-owned pages should use the standard UTM vocabulary in the Attribution & Adoption Measurement document. Country/language campaigns should use consistent campaign/content values.

## Success metrics

Primary:

- downloads/installations by market where measurable

Secondary:

- qualified visits to localized pages
- demo starts
- install-page visits
- GitHub outbound clicks
- Softaculous outbound clicks
- community/contributor activity

Diagnostic:

- reach
- engagement
- followers
- comments

Do not declare a market successful because it generated likes if it produces no meaningful installation activity.

## Rollout model

### Phase 1 — Measure

Build the opportunity matrix **and produce a search package for each serious candidate market**: local keyword set, search intent, SERP review, competitor snapshot, existing-user evidence, localization readiness, and adoption hypothesis.

Also audit current localized URLs, canonical tags, hreflang, sitemap behavior, and indexed presence before expanding the footprint.

### Phase 2 — Prepare

Ensure product truth, website localization, installation information, visuals, technical international SEO, and UTM tracking are ready for priority markets.

### Phase 3 — Pilot

Run focused campaigns/content in a small number of high-potential markets.

### Phase 4 — Learn

Compare adoption outcomes, search performance, and community feedback.

### Phase 5 — Expand

Invest further in markets that demonstrate a credible path to adoption and community sustainability.

## Guardrails

Do not:

- claim a language is fully localized without verifying it
- equate language support with country readiness
- publish machine-translated marketing without review when quality matters
- imply ChurchCRM has local payment integrations that have not been verified
- invent country-specific customers or adoption numbers
- optimize for follower count instead of installation
- create localized pages without a useful local search/user intent

## Long-term opportunity

The strongest international position is not “we have many translations.” It is:

> **Churches around the world can use an open system that respects their language, locale, budget, and need for ownership.**

That is a product and community story, not merely an SEO tactic.
