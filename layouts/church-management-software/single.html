Is ChurchCRM right for your church?

ChurchCRM works best for churches that:

  • Need practical church management — member directory, groups, attendance, giving, volunteers.
  • Want to own their data — no vendor lock-in, no subscription pressure.
  • Prefer self-hosting or simple hosting — can deploy to affordable shared hosting or their own server.
  • Work in multiple languages — benefit from community translations in 40+ languages.

ChurchCRM may not be the fit if: Your church needs integrated email campaigns, paid mobile apps, vendor phone support, or turnkey event ticketing. That's okay — those are legitimate needs, and there are products designed for them. We'll help you understand your options.

Understanding self-hosting

The software is free. Hosting isn't free, but it's affordable.

ChurchCRM runs on a standard web server (PHP + MySQL). Your costs depend on how you host:

  • Shared hosting: $5–15/month. Easy setup. Works for most churches. No technical skills required beyond following installation guides.
  • Docker / VPS: $5–50/month depending on traffic. For churches with IT volunteers. Full control.
  • Your own server: Whatever your server costs. Backup and security are your responsibility.

Pro tip: Email delivery may cost extra ($10–20/month if you send many emails). This is optional and separate from ChurchCRM.

Common questions

Can we migrate from another system?

Yes. ChurchCRM supports CSV and database imports. Setup usually takes a few hours to a day depending on data size.

Do we need technical staff?

Not necessarily. Shared hosting + installation wizard = no coding required. For Docker or custom setups, an IT volunteer helps.

Is there support if something breaks?

Community support via Discord. Documentation and forums. No paid support contract, but an active volunteer community helps.

Can we use it offline?

No. ChurchCRM is a web application. Your IT person can run it on a local server if you have no internet, but that's advanced.

What if we need customization?

Plugins and integrations exist. Custom plugins require developer skills but source code is open — you can hire someone to build what you need.

What about security and backups?

Built-in roles and permissions. Backups depend on your hosting — shared hosts usually include them; DIY hosting is your responsibility.

More questions? Check the documentation or ask in the Discord community.
